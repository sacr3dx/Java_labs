# Фургон кофе

## Структура пакетов
- `domain` — сущности: `CoffeeProduct` (абстрактный) и 4 наследника
  (`GrainCoffee`, `GroundCoffee`, `InstantJarCoffee`, `InstantSachetCoffee`),
  плюс `CoffeeVan`. Только данные и базовые инварианты, без бизнес-логики.
- `factory` — паттерны Creator / Factory Method: `CoffeeCreator` (абстрактный),
  4 конкретных Creator'а, `CoffeeCreatorRegistry` выбирает нужный по типу.
- `io` — чтение `.txt`-файла (`CoffeeFileReader`, `CoffeeRecord`).
- `comparator` — `PriceToWeightComparator implements Comparator<CoffeeProduct>`.
- `service` — бизнес-логика: `VanLoadingService` (подбор и загрузка товара
  под объём/бюджет), `QualityRangeFinder` (поиск по диапазону качества).
- `app` — `CoffeeVanApplication`: готовый прогон сценария, без пользовательского меню.

## Запуск
```
mvn test                              # все тесты
mvn compile exec:java                 # демо-прогон на bundled coffee-data.txt
mvn compile exec:java -Dexec.args=путь/к/своему/файлу.txt
```
Логи пишутся в `logs/app.log` (INFO+), `logs/error.log` (WARN/ERROR),
`logs/debug.log` (DEBUG/TRACE), и дублируются в консоль цветом по уровню.
Ротированные файлы архивируются в `logs/archive/*.log.gz`.

## Формат файла данных (`;`-разделитель)
```
grain;сорт;цена;вес_кг;качество(0-100);степень_обжарки;материал_пакета
ground;сорт;цена;вес_кг;качество;помол
instant_jar;сорт;цена;вес_кг;качество;объём_банки_л;материал_банки
instant_sachet;сорт;цена;вес_кг;качество;число_пакетиков;объём_обёртки_л
```
Строки, начинающиеся с `#`, и пустые строки пропускаются.

Обработка некорректных данных:
- **структурно битая строка** (нет типа товара, или меньше 4 обязательных
  полей sort;price;weight;quality) — строка **игнорируется** целиком, т.к.
  создать объект просто не из чего;
- **некорректное значение поля** (нечисловая цена, отрицательный вес,
  качество вне 0..100, неизвестный enum-токен) — поле **заменяется
  значением по умолчанию**, в лог пишется WARN с указанием строки файла.

Степень обжарки/помол/материал читаются регистронезависимо (`FOIL`, `foil`
— оба подходят).

## Допущения по предметной области
Плотность кофе и формула объёма упаковки заданы как разумные константы для
демонстрации паттернов, а не как справочные промышленные цифры:
- плотность: зерно 0.35 кг/л, молотый 0.40 кг/л, растворимый 0.30 кг/л;
- упаковка зерна = 5% запаса (headspace) от объёма кофе + надбавка на
  материал пакета (фольга 0.05 л, бумага 0.03 л);
- упаковка молотого — фиксированный вакуумный брикет 0.05 л;
- упаковка банки растворимого = объём банки минус объём кофе (не меньше 0);
- упаковка пакетиков = число пакетиков × объём одной обёртки.

Загрузка фургона (`VanLoadingService`) — жадный алгоритм: кандидаты
сортируются по возрастанию цены за кг (тем же `PriceToWeightComparator`,
который используется и для отображения результата), затем каждый
добавляется, если помещается и по объёму, и по остатку бюджета.
